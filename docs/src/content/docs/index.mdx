## What is Dploy?

**Dploy** turns a Helm chart into a self-service, time-boxed environment. A user picks a
template from the catalog, and Dploy spins up an isolated, per-user deployment with its own
namespace and URL — then tears it down automatically when its TTL expires.

Dploy is split into two cooperating pieces:

- **The operator** binds `DployInstanceClaim`s to environments, reconciles `DployTemplate` and
  `DployInstance` custom resources into Flux sources + `HelmRelease`s, manages warm pools, and
  enforces TTLs and quotas.
- **The API** (GoFiber + OIDC) is a thin, stateless server that authenticates users, lists the
  catalog, and files environment requests. The only thing it writes is a claim — it never touches
  Flux, and every decision about what happens next belongs to the operator.

## How it works

![Dploy architecture overview: the API writes DployInstanceClaim custom resources; the operator binds each claim to a DployInstance it owns and reconciles it into Flux resources that deploy the environment.](/diagrams/dploy-architecture.svg)

Asking for an environment means writing one object — a `DployInstanceClaim` — and watching it:

```bash
kubectl apply -f claim.yaml
kubectl get dclaim -w
# NAME               TEMPLATE   OWNER      PHASE     INSTANCE          URL
# john-doe-webterm   webterm    john-doe   Pending
# john-doe-webterm   webterm    john-doe   Bound     webterm-pool-x9   https://webterm-a1b2c3d4.env.dploy.dev
```

![DployInstanceClaim lifecycle: a claim is Pending until the operator binds an instance to it, then Bound; it is Rejected when it cannot be satisfied, and Expired once its TTL elapses.](/diagrams/dploy-claim-lifecycle.svg)

Behind that, each environment:

1. Gets an immutable 8-character UUID.
2. Is deployed into its own namespace `<owner>-<name>-<uuid>`.
3. Is exposed at a URL derived from `connectionURLTemplate` (default `<name>-<uuid>.<baseDomain>`).
4. Is owned by the claim, so deleting the claim tears it down — and so does its TTL.
